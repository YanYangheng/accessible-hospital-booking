# V2 适老预约挂号原型

这是「可用性研究与测试」课程的交互原型，以浙大二院的挂号流程为参考，聚焦第一次就诊的用户如何从找号源走到完成预约。号源、短信和预约结果均为模拟，请使用虚拟资料体验。

## 项目背景

第一轮测试中，参与者在填写首次建档资料时遇到了操作困难，也出现了建档完成后原号源失效、需要重新选号的情况。V2 围绕这两个问题调整流程，让用户更容易看清当前进度、核对已选号源，并在预约中断后接着操作。

## 设计思路

- **先找号源，再准备就诊资料。** 用户可以先选日期再找医生，也可以先选医生再看出诊日期。选定时段后，后续页面继续显示已选信息，便于核对。
- **让首次建档有两种走法。** 能在线填写的用户可以直接建档。需要工作人员协助的用户可以先预约，确认页和成功页会提示携带证件并提前一小时到院。
- **号源失效后可以接着选。** 在模拟失效的情境中，用户可以保留就诊资料，直接查看同科室的其他号源。
- **让操作结果看得见。** 预约成功后可在「我的预约」核对结果。界面适配手机竖屏，宽屏中以居中的手机画布呈现。

## 设计亮点

- **四步进度提示。** 页面顶部标出「选择号源」「登录核验」「患者信息」「确认预约」，并突出当前步骤，方便用户知道自己做到哪里、后面还有哪些步骤。
- **在选号时就看清状态和费用。** 科室页可按名称搜索。医生列表会标出约满状态，时段页把时间、号别和费用放在同一选项里，便于选中前比较。
- **减少建档时的重复填写。** 证件号通过校验后，表单自动填入性别和出生日期。证件号有误时，页面在对应字段旁提示，方便用户定位问题。
- **到院建档有图文指引。** 用户可以查看所选院区的办理指引。确认页和预约成功页也会重复提示携带证件并提前一小时到院，方便提交后再核对。

## 在线体验与操作方法

| 入口 | 适合谁 | 进入后的行为 |
| --- | --- | --- |
| [自由体验](https://hospital-ux-test.yanyangheng.com/?mode=debug&page=home) | 想试用原型的访客 | 直接进入预约首页。操作记录和预约表单均不上传。 |
| [参与测试](https://hospital-ux-test.yanyangheng.com/) | 受邀参加可用性测试的参与者 | 从测试封面填写测试用名后开始。系统保存操作记录和提交的预约资料，用于研究分析。 |

1. 选择院区和科室，再按医生或按日期查找可预约的时段。
2. 填写手机号并完成模拟短信验证。手机号可用 `13800000000`，验证码接受任意六位数字。
3. 选择在线建档或线下人工协助建档。在线建档请使用虚拟资料，证件号需符合原型的格式和校验码规则。
4. 核对院区、科室、医生、日期和时段，再提交预约。提交后可在「我的预约」查看结果。

## 技术文档

### 本地运行

前端使用 HTML、CSS 和原生 JavaScript。后端使用 Python 3 标准库提供 HTTP 服务，并通过 SQLite 保存测试记录。

```sh
git clone https://github.com/YanYangheng/accessible-hospital-booking.git
cd accessible-hospital-booking
python3 server.py
```

启动后可打开 [本地自由体验](http://127.0.0.1:8767/?mode=debug&page=home) 或 [本地参与测试](http://127.0.0.1:8767/)。同一局域网中的设备可用服务器 IP 加端口 `8767` 访问。

### 入口与测试情境

| 路径或参数 | 行为 |
| --- | --- |
| `/` | 打开参与测试的封面，也可恢复同一浏览器保存的测试进度。 |
| `/?mode=debug&page=home` | 自由体验，从预约首页开始。 |
| `/?mode=debug&page=archive` | 使用示例资料直接打开建档页。 |
| `/?mode=debug&page=confirm&random=1` | 随机选取可预约的医生和时段，打开确认页。 |
| `/?expiry=1` | 模拟建档完成时原号源失效，提示查看同科室其他号源。 |
| `/?delay=1` | 模拟首次未收到短信，等待 30 秒后可重发。 |
| `/?mode=test&skip_cover=1&test_id=P03&name=TestUser` | 通过预填的测试编号和测试用名直接进入测试。 |

自由体验入口会清除当前浏览器在该站点保存的测试进度。

### 记录与存储

数据库默认位于 `data/study.sqlite3`，可用 `--database` 指定其他位置。参与测试时，浏览器在本地保存进度并在中断后尽力补传日志。恢复时请使用同一浏览器和访问地址。

| 数据表 | 内容 |
| --- | --- |
| `sessions`、`attempts` | 测试会话、预约尝试与测试情境 |
| `events` | 页面访问、点击与校验结果，按会话和顺序号记录 |
| `session_returns` | 恢复测试的记录 |
| `submissions` | 最终预约、建档方式与提交的表单字段 |

提交记录会保留原始表单字段，请只填写测试资料。数据库目录 `data/` 已加入 Git 忽略规则。

### Nginx 反向代理

Nginx 与 Python 同机部署时，可让后端监听回环地址，并仅信任指定代理传入的客户端地址。

```sh
python3 server.py --bind 127.0.0.1 --port 8767 --trusted-proxy 127.0.0.1
```

```nginx
location / {
    proxy_pass http://127.0.0.1:8767;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
}
```

局域网直连时省略 `--trusted-proxy`。代理和后端分开部署时，填写后端实际看到的代理 IP，并限制后端端口仅允许代理访问。
